# Authentication Architecture

## Purpose

The authentication system is responsible for identifying users, establishing authenticated sessions, and controlling access to protected functionality throughout the platform.

Authentication is designed to provide a simple user experience while maintaining secure session management and permission enforcement.

## Core Principles

```
- Email-first authentication
- JWT cookie authentication
- Frontend-managed authentication state
- Backend-managed authentication security
- Minimal account complexity
```

## Authentication Identity

Users authenticate using an email address and password.

The platform intentionally removes username-based authentication in favour of a single authentication identifier.

This simplifies account management and provides a consistent login experience throughout the application.

## Session Management

Authenticated sessions are established using JWT cookies.

Authentication tokens are stored and managed by the backend through secure HTTP cookies.

The frontend does not manually store authentication tokens.

Authentication cookies are automatically included with authenticated requests.

## Frontend Responsibilities

The frontend is responsible for:

```
- Displaying authentication interfaces
- Submitting authentication requests
- Managing authentication state
- Controlling authenticated UI rendering
- Protecting frontend routes
```

The frontend determines what should be displayed to the user based on the current authentication state.

## Backend Responsibilities

The backend is responsible for:

```
- Validating credentials
- Creating authenticated sessions
- Managing JWT tokens
- Validating authentication requests
- Enforcing permissions
- Protecting API endpoints
```

The backend remains the source of truth for authentication and authorisation decisions.

## Authentication Workflow

```text
User submits credentials
        ↓
Frontend sends authentication request
        ↓
Backend validates credentials
        ↓
Authenticated session created
        ↓
Frontend loads authenticated user information
        ↓
Protected functionality becomes available
```

## User States

The platform supports two primary authentication states.

### Anonymous User

```
- Not authenticated
- Can access public functionality
- Cannot access protected functionality
```

### Authenticated User

```
- Successfully authenticated
- Has an active authenticated session
- Can access protected functionality
```

## Permission Model

Authentication determines who a user is.

Permissions determine what a user is allowed to do.

Authentication alone does not grant access to protected resources.

Permission checks are enforced by the backend for all protected functionality.

## Architectural Goal

The authentication architecture is designed to separate user experience concerns from security concerns.

```
Frontend manages authentication state.

Backend manages authentication security.
```

This separation keeps authentication predictable, maintainable, and secure throughout the platform.
