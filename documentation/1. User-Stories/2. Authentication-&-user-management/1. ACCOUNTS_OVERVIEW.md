# Accounts Overview

## Purpose

The Accounts app is responsible for user authentication, account management, and account lifecycle functionality throughout the platform.

The app extends Django's default authentication system to provide a simplified email-based authentication workflow.

## Responsibilities

The Accounts app is responsible for:

```text
- User authentication
- User registration
- Account deactivation
- Account reactivation
- User serialization
- Authentication integration
```

## Core Components

The Accounts app currently consists of the following areas:

```text
- Custom User Model
- Custom User Manager
- Registration Customization
- User Serializers
- Account Deactivation
- Account Reactivation
```

## Authentication Approach

The platform uses email-based authentication instead of username-based authentication.

Users authenticate using:

```text
- Email Address
- Password
```

Authentication is integrated with the platform authentication system and frontend authentication state management.

## Account Lifecycle

The Accounts app manages the complete user account lifecycle.

Supported account states:

```text
- Active Account
- Deactivated Account
```

Accounts are deactivated rather than permanently deleted.

This allows previously deactivated accounts to be restored through the reactivation workflow.

## API Responsibilities

The Accounts app exposes functionality for:

```text
- Account Deactivation
- Reactivation Requests
- Account Reactivation Confirmation
```

These endpoints are consumed by the frontend account management features.

## Frontend Relationship

The frontend relies on the Accounts app for:

```text
- Registration
- Authentication State
- Account Deactivation
- Account Reactivation
- User Information
- Permission-Based Rendering
```

Authenticated user information is exposed through custom serializers and consumed by the frontend authentication system.
