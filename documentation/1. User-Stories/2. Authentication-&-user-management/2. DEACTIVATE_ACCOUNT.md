# Account Deactivation

## Purpose

Account Deactivation allows an authenticated user to disable their account without permanently deleting it.

The feature uses a confirmation step before the account is deactivated.

## User Goal

The user wants to deactivate their account while keeping the option to reactivate it later.

## User Flow

```text
User opens the account deactivation section
    ↓
User clicks deactivate account
    ↓
Frontend displays confirmation step
    ↓
User confirms deactivation
    ↓
Frontend sends deactivation request
    ↓
Backend deactivates the account
    ↓
Frontend logs the user out
    ↓
User is redirected to the home page
```

## Frontend Behaviour

The account deactivation form stores:

```text
- Confirmation State
- Validation Errors
- Loading State
```

The confirmation state controls whether the user is viewing the initial deactivation button or the final confirmation step.

## Confirmation Behaviour

The feature requires confirmation before sending the deactivation request.

This helps prevent accidental account deactivation.

The user can either:

```text
- Confirm Deactivation
- Cancel
```

## Submission Behaviour

When the form is submitted, the frontend prevents duplicate submissions while the request is loading.

If deactivation succeeds:

```text
- Account is deactivated
- User is logged out
- User is redirected to the home page
```

If deactivation fails:

```text
- Validation errors are stored
- General errors are displayed where relevant
- Loading state is cleared
```

## Backend Relationship

The backend is responsible for:

```text
- Identifying the authenticated user
- Marking the account as inactive
- Recording the deactivation timestamp
- Removing authentication cookies
- Returning success or error responses
```

The frontend does not deactivate the account directly.

It submits the request to the backend and updates the interface based on the response.

## Account Data Behaviour

Account deactivation does not permanently delete the user's account.

The account is retained so it can be restored later through the account reactivation feature.

## Warning Message

The form displays a warning explaining that:

```text
- The account will be deactivated
- User data will be retained
- The account can be reactivated later
```

## Error Handling

The account deactivation feature supports general request errors.

Examples include:

```text
- Account deactivation failed
- Authentication failure
- Server validation failure
```
