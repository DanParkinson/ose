## Purpose

The platform uses custom email verification templates to control the content and branding of verification emails sent during registration.

These templates replace Django Allauth's default email content and provide a verification experience that matches the platform's frontend workflow.

## Why Custom Templates Are Used

The default Allauth templates:

```text
Use generic messaging
Use generic branding
Do not match the frontend verification flow
```

Custom templates allow the platform to:

```text
Provide consistent messaging
Direct users to the frontend application
Maintain platform branding
Control verification instructions
```

This creates a more cohesive registration experience.

## Template Structure

The verification email consists of two templates:

```text
email_confirmation_signup_subject.txt
email_confirmation_signup_message.txt
```

The subject template controls the email subject line.

The message template controls the email body.

This separation follows Django Allauth's email templating system.

## Subject Template

The subject template defines the title shown in the recipient's inbox.

Example:

```text
Verify your email address
```

The purpose of the subject is to clearly communicate that the email relates to account verification.

## Message Template

The message template contains the verification instructions sent to the user.

Example:

```text
Hello,

Thank you for registering an account with Open-Source Education.

Please verify your email address by clicking the link below:

{{ frontend_url }}/verify-email/{{ key }}

If you did not create this account, you can safely ignore this email.

Thanks,
OSE
```

The template includes:

```text
Registration confirmation
Verification instructions
Verification link
Security guidance
Platform branding
```

## Frontend Verification Relationship

The verification email directs users to the frontend verification route.

The verification link is generated using:

```text
{{ frontend_url }}/verify-email/{{ key }}
```

Where:

```text
frontend_url
```

is provided by the custom account adapter and:

```text
key
```

is generated by Django Allauth.

This allows the email verification process to begin from the frontend application rather than a backend confirmation page.

## User Experience

From the user's perspective:

```text
User registers
        ↓
Verification email received
        ↓
Verification link clicked
        ↓
Frontend verification page opens
        ↓
Verification completed
        ↓
User can login
```

The user remains within the platform's frontend experience throughout the verification process.

## Architecture Relationship

The verification template sits between:

```text
Registration
        ↓
Email Generation
        ↓
Verification Email Template
        ↓
Email Delivery
        ↓
Frontend Verification Route
```

The template is responsible for the content delivered to the user, while Django Allauth manages verification token generation and validation.

By separating content from verification logic, the platform can update messaging and branding without changing the underlying authentication workflow.
