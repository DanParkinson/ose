# AuthContext

## Purpose

AuthContext provides a shared authentication state for the React application.

It allows the application to understand whether a user is authenticated and gives components access to common authentication actions.

## Responsibilities

AuthContext is responsible for:

```text
- Storing the current user
- Tracking authentication loading state
- Checking the current session
- Exposing authentication actions
- Updating global authentication state
```

## Application Role

AuthContext acts as the central frontend authentication layer.

It prevents individual components from needing to manage authentication state independently.

Instead, authentication state is stored once and shared across the application.

## AuthProvider

AuthProvider wraps the application near the root of the frontend.

This makes authentication state available to all routes and components inside the provider.

The provider exposes:

```text
- user
- setUser
- loading
- login
- logout
- register
- changePassword
```

## User State

The user state represents the currently authenticated user.

Possible values:

```text
- null
- authenticated user object
```

A `null` user means the frontend should treat the visitor as unauthenticated.

An authenticated user object means the frontend can render authenticated UI.

## Loading State

The loading state represents whether the application is still checking the current session.

This is important because the frontend should not decide whether to redirect or render protected pages before the session check has completed.

## Session Checking

When the application loads, AuthContext checks whether the browser already has a valid authenticated session.

This allows users to remain authenticated after refreshing the page or returning to the application.

## Authentication Actions

AuthContext exposes reusable authentication actions.

```text
- login
- logout
- register
- changePassword
```

These actions centralise authentication-related API requests and return consistent success or error responses to the components that use them.

## Component Relationship

Components access AuthContext through the `useAuth` hook.

This allows components to:

```text
- Read the current user
- Check loading state
- Trigger authentication actions
- Update UI based on authentication state
```

Components should not import AuthContext directly unless necessary.

## Backend Relationship

AuthContext communicates with the backend authentication endpoints through the shared API configuration.

The backend remains responsible for:

```text
- Validating credentials
- Issuing authentication cookies
- Validating sessions
- Enforcing permissions
```

AuthContext only manages the frontend state created from those backend responses.

## Design Principles

AuthContext is designed around:

```text
- Centralised authentication state
- Reusable authentication actions
- Consistent form responses
- Frontend session awareness
- Separation of frontend state from backend security
```

The goal is to keep authentication state predictable and avoid duplicating authentication logic across components.
