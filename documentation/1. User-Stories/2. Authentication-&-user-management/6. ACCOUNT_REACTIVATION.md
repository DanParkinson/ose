# Account Reactivation

## Purpose

Account reactivation allows a previously deactivated user account to be restored.

The system is designed to let users regain access to their account without creating a new account.

## Responsibilities

Account reactivation is responsible for:

```text
- Accepting reactivation requests
- Finding inactive accounts
- Generating secure reactivation tokens
- Sending reactivation emails
- Validating reactivation links
- Restoring inactive accounts
```

## Reactivation Approach

The platform uses an email-based reactivation workflow.

A user submits their email address.

If a matching deactivated account exists, the backend generates a secure reactivation link and sends it to the account email address.

The response does not reveal whether an account exists.

## Reactivation Request Workflow

```text
User submits email address
    ↓
Backend checks for inactive account
    ↓
If inactive account exists, token is generated
    ↓
Reactivation link is sent by email
    ↓
Generic success response is returned
```

## Reactivation Confirmation Workflow

```text
User opens reactivation link
    ↓
Frontend submits uid and token
    ↓
Backend validates uid
    ↓
Backend validates token
    ↓
Account is marked active
    ↓
Deactivation timestamp is cleared
```

## Account State

After successful reactivation, the account is restored to an active state.

```text
is_active = True
deactivated_at = None
```

The user can then authenticate again using their normal login credentials.

## Security Behaviour

The reactivation request response is intentionally generic.

This prevents users from discovering whether a particular email address belongs to a deactivated account.

Reactivation links rely on secure token validation before an account can be restored.

## Email Relationship

The reactivation system depends on the configured email backend.

During development, reactivation emails are printed to the console.

In production, the email backend should be replaced with a real email provider.

## Frontend Relationship

The frontend is responsible for:

```text
- Displaying the reactivation request form
- Submitting the user's email address
- Displaying the reactivation confirmation route
- Submitting the uid and token
- Showing success or error messages
```

The backend remains responsible for account lookup, token validation, and restoring the account.

## Design Principles

The account reactivation system is designed around:

```text
- Secure account restoration
- Email-based verification
- Non-revealing responses
- Account lifecycle continuity
- Soft account recovery
```

The goal is to allow users to restore access to a deactivated account while avoiding unnecessary account duplication.
