# Account Deactivation

## Purpose

Account deactivation allows an authenticated user to disable their account without permanently deleting it from the database.

The system is designed to preserve account data while preventing the user from continuing to access protected functionality.

## Responsibilities

Account deactivation is responsible for:

```text
- Marking a user account as inactive
- Recording when the account was deactivated
- Ending the authenticated session
- Removing authentication cookies
- Preventing further authenticated access
```

## Deactivation Approach

The platform uses soft account deactivation.

A deactivated account is not deleted.

Instead, the account is marked as inactive and the deactivation time is stored.

This allows the account to be restored later through the account reactivation workflow.

## User Requirements

Only authenticated users can deactivate their own account.

The user must have an active authenticated session before the deactivation request can be made.

## Deactivation Workflow

```text
Authenticated user submits deactivation request
    ↓
Backend identifies the current user
    ↓
Account is marked inactive
    ↓
Deactivation timestamp is stored
    ↓
Authentication cookies are removed
    ↓
User session ends
```

## Account State

After deactivation, the account is updated to an inactive state.

```text
is_active = False
deactivated_at = current time
```

This prevents the account from being used for normal authenticated access.

## Session Handling

When an account is deactivated, the current authentication session is ended.

Authentication cookies are removed so the frontend no longer treats the user as authenticated.

## Frontend Relationship

The frontend uses account deactivation to allow users to disable their own account.

The frontend is responsible for:

```text
- Displaying the deactivation interface
- Submitting the deactivation request
- Handling the success response
- Updating authentication state
- Redirecting the user if required
```

The backend remains responsible for actually deactivating the account.

## Reactivation Relationship

Account deactivation is designed to work alongside account reactivation.

A deactivated account can later be restored through the reactivation workflow.

This avoids permanent deletion while still allowing users to disable access to their account.

## Design Principles

The account deactivation system is designed around:

```text
- Soft account removal
- Account data preservation
- Secure session termination
- Future account restoration
- Clear account lifecycle management
```

The goal is to give users control over their account while preserving the ability to restore access later.
