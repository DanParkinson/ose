# Change Password

## Purpose

Change Password allows an authenticated user to update their account password.

The feature requires the user to provide their current password before choosing a new password.

## User Goal

The user wants to update their password using:

```text
- Current Password
- New Password
- Confirm New Password
```

## User Flow

```text
User opens the change password form
    ↓
User enters their current password
    ↓
User enters and confirms a new password
    ↓
User submits the form
    ↓
Frontend sends password change request
    ↓
Backend validates the password data
    ↓
If successful, the form is cleared and a success message is displayed
    ↓
If unsuccessful, validation errors are displayed
```

## Frontend Behaviour

The change password form stores:

```text
- Current Password
- New Password
- Confirm New Password
- Validation Errors
- Success Message
- Loading State
```

When the user edits a field, the related error is cleared.

This allows the form to remove old validation messages as the user corrects their input.

## Form Fields

The change password form contains:

```text
- Current Password
- New Password
- Confirm New Password
```

## Submission Behaviour

When the form is submitted, the frontend prevents duplicate submissions while the request is loading.

The password change request is sent through the shared authentication system.

If the request succeeds:

```text
- Password fields are cleared
- Success message is displayed
```

If the request fails:

```text
- Validation errors are stored
- Field errors are displayed
- General errors are displayed where relevant
- Loading state is cleared
```

## Backend Relationship

The backend is responsible for:

```text
- Checking the current password
- Validating the new password
- Checking the password confirmation
- Updating the user's password
- Returning validation errors
```

The frontend does not update the password directly.

It submits the password change details to the backend and displays the response.

## Error Handling

The change password feature supports field-level errors.

Examples include:

```text
- Current password errors
- New password errors
- Password confirmation errors
```

The feature also supports non-field errors for general password change failures.

## Important Configuration

The backend must require the old password for password changes.

```text
OLD_PASSWORD_FIELD_ENABLED = True
```

Without this setting, the backend may allow password changes without validating the current password.
