# User Serializers

## Purpose

The Accounts app provides custom serializers to support the platform's authentication workflows and frontend integration.

The serializers are responsible for validating registration data and exposing authenticated user information to the frontend.

## Responsibilities

The user serializers are responsible for:

```text
- Registration validation
- Email uniqueness validation
- Authenticated user serialization
- Frontend authentication support
- Permission-aware user data exposure
```

## Registration Serializer

The platform uses a custom registration serializer to modify the default registration behaviour.

The serializer supports:

```text
- Email-based registration
- Email uniqueness validation
- Username removal
```

The registration process is intentionally simplified to require only the information necessary to create an account.

## Email Validation

The registration serializer validates email uniqueness before account creation.

This prevents:

```text
- Duplicate accounts
- Conflicting authentication identities
```

Users must register with an email address that is not already associated with an existing account.

## Authenticated User Serializer

The platform uses a custom user details serializer to expose authenticated user information to the frontend.

The serializer currently provides:

```text
- User ID
- Email Address
- Staff Status
- Superuser Status
```

The serializer intentionally exposes only the information required by the frontend.

## Frontend Integration

The frontend consumes serialized user data to support:

```text
- Authentication state management
- Protected route handling
- Permission-based rendering
- Administrative interface access
```

The frontend uses serialized user information to determine what should be displayed to the user.

## Permission-Aware Rendering

Administrative status information is exposed to support conditional frontend rendering.

Examples include:

```text
- Admin navigation
- Administrative dashboards
- Staff-only functionality
```

Frontend visibility checks improve user experience but do not replace backend permission enforcement.
