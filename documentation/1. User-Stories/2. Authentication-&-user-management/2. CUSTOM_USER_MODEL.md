# Custom User Model

## Purpose

The platform uses a custom user model instead of Django's default user model.

The custom user model supports the platform's email-first authentication approach and account lifecycle management features.

## Responsibilities

The custom user model is responsible for:

```text
- User authentication identity
- User account creation
- Superuser creation
- Password handling
- Account activation state
- Account deactivation tracking
```

## Authentication Identity

The platform uses email addresses as the primary authentication identifier.

Users authenticate using:

```text
- Email Address
- Password
```

Username-based authentication is intentionally removed from the platform.

This provides a simpler and more consistent authentication experience.

## User Management

The custom user model uses a custom user manager.

The user manager is responsible for:

```text
- User creation
- Superuser creation
- Email validation
- Email normalization
- Password hashing
```

All user creation workflows pass through the custom manager.

## Account States

The user model supports two account states.

### Active

```text
- Account can authenticate
- Account can access protected functionality
```

### Deactivated

```text
- Account cannot authenticate
- Account cannot access protected functionality
- Account remains stored in the database
```

Deactivated accounts can later be restored through the account reactivation workflow.

## Account Lifecycle Support

The user model tracks account deactivation activity.

This allows the platform to:

```text
- Preserve user accounts
- Support account restoration
- Avoid permanent account deletion
```

The platform uses account deactivation rather than immediate account removal.

## Authentication Integration

The custom user model integrates with:

```text
- Django Authentication
- django-allauth
- dj-rest-auth
- JWT Authentication
```

All authentication workflows operate through the custom user model.

## Frontend Relationship

The frontend receives authenticated user information from the custom user model through dedicated serializers.

This information supports:

```text
- Authentication state management
- Permission-based rendering
- Administrative interface access
```

The frontend never interacts with the model directly.

All communication occurs through API endpoints and serializers.
