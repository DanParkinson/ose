## Purpose

Serializers control how model instances are converted to API data and how submitted API data is validated.

The current implemented serializer pattern uses Django REST Framework `ModelSerializer`.

## Implemented Serializers

| Serializer | Model | Purpose | Implemented |
|---|---|---|---|
| `SubjectSerializer` | `Subject` | Serialize and validate subject data | :white_check_mark: |

## ModelSerializer Pattern

The platform currently uses DRF `ModelSerializer` for model-based API resources.

Example:

```py
class SubjectSerializer(serializers.ModelSerializer):
    class Meta:
        model = models.Subject
        fields = [
            "subject_id",
            "title",
            "slug",
            "level",
            "language",
            "is_published",
            "is_protected",
        ]
        read_only_fields = [
            "subject_id",
            "slug",
        ]
```

`ModelSerializer` keeps the serializer closely connected to the Django model while still allowing explicit control over exposed fields.

## Field Declaration

Serializer fields are explicitly declared.

```py
fields = [
    "subject_id",
    "title",
    "slug",
    "level",
    "language",
    "is_published",
    "is_protected",
]
```

Explicit field declarations make the API response easier to understand and reduce the risk of accidentally exposing unwanted model fields.

## Read-Only Fields

Generated or backend-managed fields are marked as read-only.

```py
read_only_fields = [
    "subject_id",
    "slug",
]
```

This means the frontend can receive these values in API responses, but cannot directly submit or modify them.

Current read-only fields:

| Field | Reason |
|---|---|
| `subject_id` | Generated UUID identifier |
| `slug` | Generated by the backend |

## Serializer Responsibilities

The serializer is responsible for:

```text
Defining API response fields
Validating submitted data
Protecting read-only fields
Converting model instances into JSON-compatible data
Supporting list, create, detail, update, and delete views
```

The serializer does not decide permissions, filtering, pagination, or caching. Those responsibilities belong to views and API configuration.
