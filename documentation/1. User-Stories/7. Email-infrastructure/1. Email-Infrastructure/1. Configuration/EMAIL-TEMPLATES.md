## Purpose

Email templates define the content of email messages generated by the platform.

Templates separate email content from application logic, allowing email text to be customised without modifying the underlying authentication or email delivery systems.

## Template Role

When an email is generated, Django renders the appropriate email template before passing the completed message to the configured email backend.

The template system is responsible for:

```text
Email Subject Content
Email Body Content
Dynamic Content Placement
User-facing Email Messaging
```

The template system is not responsible for:

```text
Email Delivery
Email Verification Logic
Password Reset Logic
Authentication Decisions
```

These responsibilities belong to the authentication and email infrastructure systems.

## Template Structure

Email templates are divided into two components:

```text
Subject Template
Message Template
```

The subject template defines the email subject line.

The message template defines the email body content.

This separation allows subject lines and message content to be maintained independently.

## Subject Templates

Subject templates are responsible for generating email subject lines.

Example:

```text
Verify your email address
```

Subject templates should remain concise and clearly identify the purpose of the email.

## Message Templates

Message templates are responsible for generating the email body.

Message templates may contain:

```text
Static Content
Dynamic Variables
Verification Links
Password Reset Links
User Information
```

Dynamic values are inserted when the email is generated.

Example:

```text
{{ key }}
{{ uid }}
{{ token }}
```

## Template Overrides

The platform uses template overrides to customise the content generated by third-party packages such as Django Allauth and DJ-Rest-Auth.

Template overrides allow platform-specific messaging to be used while continuing to rely on the underlying authentication workflows.

This approach provides:

```text
Custom Branding
Custom Messaging
Custom Frontend URLs
Consistent User Experience
```

without requiring modification of package source code.

## Plain Text Templates

The platform currently uses plain text email templates.

Plain text templates provide:

```text
Simple Maintenance
Easy Testing
Maximum Email Client Compatibility
Fast Development Workflow
```

Plain text templates are sufficient for development and initial production releases.

## Production Relationship

The template system is independent of the configured email backend.

Changing the email delivery provider does not require email templates to be modified.

Templates define the content of an email, while the email backend determines how that email is delivered.
